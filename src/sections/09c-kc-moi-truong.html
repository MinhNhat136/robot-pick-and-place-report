MỤC IV.02 · CÀI ĐẶT MÔI TRƯỜNG

Chuẩn bị hai máy để chạy lại các kịch bản.

Các mục IV.02–IV.04 hướng dẫn tự chạy lại các kịch bản để kiểm chứng số liệu trong báo cáo. Cần hai máy: máy trạm chạy mô phỏng và notebook (client), máy chủ GPU của khách hàng chạy GR00T (server). Mục này cài đặt cả hai phía; khởi động server và chạy đánh giá được trình bày ở IV.03 và IV.04.

Notebook trên máy trạm gửi ảnh camera, trạng thái khớp và câu lệnh tới GR00T server; server trả về một chuỗi action. Hai máy có thể nối thẳng qua mạng nội bộ, hoặc qua SSH tunnel nếu server chỉ nghe ở 127.0.0.1.

Yêu cầu phần cứng và phần mềm

MÁY TRẠM · CLIENT
Mô phỏng và notebook
  • Ubuntu 24.04, GPU NVIDIA có RTX (dự án dùng RTX 5090), driver 580
  • Isaac Sim 6.0.1 cài cục bộ tại ~/isaac-sim-6 (Python 3.12)
  • Isaac Lab release/3.0.0-beta2 tại ~/IsaacLab, cài vào cùng Python của Isaac Sim
  • Isaac Lab Arena release/0.2.1 tại ~/IsaacLab-Arena (nguồn file YAML khớp và modality config)
  • uv, make, git; truy cập Internet cho lần cài đầu
MÁY CHỦ · SERVER
GPU server của khách hàng
  • Linux, GPU NVIDIA hỗ trợ CUDA (dự án dùng 1× H100 80 GB)
  • Isaac-GR00T commit 4b1dca9, môi trường uv (Python 3.10), ffmpeg
  • Quyền truy cập Hugging Face tới model gốc nvidia/GR00T-N1.7-3B (đã chấp nhận giấy phép NVIDIA)
  • Checkpoint trong models/ và modality config của từng kịch bản (card 5)
  • Mở được cổng cho máy trạm, hoặc cho phép SSH
Giữ đúng cặp phiên bản: toàn bộ kết quả trong báo cáo đo trên Isaac Sim 6.0.1 + Isaac Lab 3.0.0-beta2 và Isaac-GR00T 4b1dca9. Isaac Sim 6.1 cần driver ≥ 595 và chưa được kiểm thử với mã nguồn này.

Đặt gói sản phẩm trên máy trạm

Mã nguồn đọc assets/, datasets/ và models/ theo đường dẫn ~/workspace/shimizu-robot/, nên giải nén gói đúng vị trí này. Isaac Sim, Isaac Lab và Arena đặt trong thư mục home như card 2.

~/workspace/shimizu-robot/      # gói sản phẩm (IV.01)
├── codes/standalone_g1_gr00t/  # client: package g1gr00t, notebook, Makefile
├── assets/                     # nucleus_cache + táo, đĩa
├── datasets/                   # dataset LeRobot
└── models/                     # checkpoint (chép lên server, card 6)
~/isaac-sim-6/   ~/IsaacLab/   ~/IsaacLab-Arena/
Cài ở vị trí khác: Makefile cho phép ghi đè ISAAC_PY (Python của Isaac Sim), ARENA_DIR và ISAAC_GR00T_DIR, ví dụ make sim-test ISAAC_PY=/opt/isaac-sim/python.sh. Đường dẫn dataset và model nằm trong configs/*.yaml.

Cài client trên máy trạm

Package standalone_g1_gr00t dùng hai môi trường: .venv (Python 3.10, cho kiểm thử và notebook không mô phỏng) và Python của Isaac Sim (cho notebook có mô phỏng).

cd ~/workspace/shimizu-robot/codes/standalone_g1_gr00t

# môi trường .venv
make venv            # uv venv .venv --python 3.10, cài package + dev + notebook
make sync            # chép 4 file YAML khớp/WBC từ ~/IsaacLab-Arena, ghi hash nguồn
make assets          # tải policy chân AGILE (ONNX) vào assets/wbc/
make test            # unit test không cần mô phỏng

# môi trường Isaac Sim
export PYTHONNOUSERSITE=1   # không để gói trong ~/.local chen vào Python của Isaac Sim
make sim-install     # cài package vào ~/isaac-sim-6/python.sh
make sim-test        # unit test bằng Python của Isaac Sim
make sim-test-scene  # test có scene: robot đứng vững, bàn / táo / đĩa
make sim-kernel      # đăng ký kernel Jupyter "isaacsim6" cho notebook mô phỏng

Cài server trên máy chủ GPU

Cài Isaac-GR00T đúng commit đã dùng khi huấn luyện. Bảng dưới cho biết mỗi kịch bản cần checkpoint và modality config nào; cách đưa chúng lên server ở card 6.

# cần sẵn: git, uv, ffmpeg (sudo apt-get install -y ffmpeg)
git clone https://github.com/NVIDIA/Isaac-GR00T.git ~/Isaac-GR00T
cd ~/Isaac-GR00T
git checkout 4b1dca9d88d2a0b9ea5a65aa61c82ff89f5c4f0e
git submodule update --init --recursive
uv sync --python 3.10      # tạo môi trường, cài GR00T và thư viện GPU (vài phút)
uv run python -c "import gr00t, torch; print('GR00T ok | CUDA', torch.cuda.is_available())"
# nếu model gốc chưa có trong cache Hugging Face, đăng nhập bằng tài khoản
# đã chấp nhận giấy phép nvidia/GR00T-N1.7-3B:

Đưa checkpoint bàn giao lên server

Ba checkpoint fine-tune nằm trong thư mục models/ của gói bàn giao, mỗi thư mục dùng được ngay với GR00T server: trọng số (3 file safetensors), cấu hình, processor và thống kê chuẩn hoá. Chỉ cần chép những checkpoint của kịch bản muốn kiểm chứng.

BƯỚC 1
Tạo thư mục trên server
Ví dụ ~/shimizu-robot/models
BƯỚC 2
Chép checkpoint
rsync từ máy trạm, chạy tiếp được nếu bị ngắt
BƯỚC 3
Kiểm tra toàn vẹn
So checksum hai phía, đủ 3 file trọng số
BƯỚC 4
Chép modality config
Bản của Arena cho kịch bản táo và búa
# chạy trên máy trạm
SRV=user@gpu-server
CKPTS="hammer_to_bin_mix200 hammer_to_bin_mix400 real2sim_multi_fruit"
cd ~/workspace/shimizu-robot/models

# bước 1 — tạo thư mục trên server
ssh $SRV 'mkdir -p ~/shimizu-robot/models ~/shimizu-robot/configs'

# bước 2 — chép checkpoint cần dùng, giữ nguyên thư mục con
rsync -avP $CKPTS $SRV:~/shimizu-robot/models/

# bước 3 — so checksum, không chép (-n):
# không liệt kê file nào nghĩa là hai phía giống hệt
rsync -avnc $CKPTS $SRV:~/shimizu-robot/models/
# đếm file trọng số: kỳ vọng 9 (3 checkpoint × 3 file)
ssh $SRV 'ls ~/shimizu-robot/models/*/*/checkpoint-*/*.safetensors | wc -l'

# bước 4 — modality config của Arena (kịch bản táo, búa)
G1=~/IsaacLab-Arena/isaaclab_arena_gr00t/embodiments/g1
rsync -avP $G1/g1_sim_wbc_data_gr00t_n_1_7_config.py \
      $SRV:~/shimizu-robot/configs/
Thư mục trong models/Đường dẫn --model-path trên server
hammer_to_bin_mix200/~/shimizu-robot/models/hammer_to_bin_mix200/
hammer_mix200_n17/checkpoint-10000
hammer_to_bin_mix400/~/shimizu-robot/models/hammer_to_bin_mix400/
hammer_mix400_n17/checkpoint-20000
real2sim_multi_fruit/~/shimizu-robot/models/real2sim_multi_fruit/
g1_fruits_n17_bs32_20k/checkpoint-20000
Không qua mạng được? Chép thư mục models/ bằng ổ cứng ngoài rồi đặt trên server theo cùng cấu trúc; vẫn chạy bước 3 bằng sha256sum trên các file safetensors ở hai phía. Checkpoint táo → đĩa của NVIDIA không có trong gói: tải thẳng từ Hugging Face về server.
7

Thiết lập kết nối

Chọn một trong hai cách. Cổng phía server phải trùng cổng client mong đợi (card 5); có thể đổi cổng client bằng biến môi trường NB10_PORT, NB12_PORT hoặc trường server.port trong file YAML.

CÁCH 1
Mạng nội bộ
  • Server nghe --host 0.0.0.0
  • Mở cổng của kịch bản trên firewall cho riêng máy trạm
  • Client đặt host là IP server, ví dụ NB12_HOST=10.0.0.5
CÁCH 2
SSH tunnel
  • Server nghe --host 127.0.0.1, không mở cổng ra ngoài
  • Máy trạm mở tunnel và để chạy suốt lúc đánh giá
  • Client giữ host mặc định 127.0.0.1
# cách 2, trên máy trạm (ví dụ kịch bản búa, cổng 5557)
ssh -N -L 5557:127.0.0.1:5557 user@gpu-server
