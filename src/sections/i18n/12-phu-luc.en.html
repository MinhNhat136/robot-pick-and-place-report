A

Glossary

VLAA model that takes images and language and directly outputs robot control commands
Foundation modelA model pre-trained on large data; fine-tuned for a specific task with little data
EmbodimentA specific type of robot body (joints, cameras, hands)
Action chunkThe sequence of actions the model returns in one inference (40 steps = 0.8 s at 50 Hz)
Flow matching / DiTA technique that generates continuous data by gradual denoising, used to generate action chunks
TeleopA person controlling the robot remotely (VR headset) to create demonstration data
Open-loop / closed-loopEvaluation on pre-recorded data / the model controlling the robot continuously by itself
Real2simTransferring data from the real world into simulation
Domain gapThe difference between the training environment and the runtime environment
Visual gapThe model's success rate drops when the scene looks different at runtime than during data recording (apple task 92 → 56 → 0 %)
Domain randomizationRandomly varying lighting, materials, background and camera angle in simulation so the model does not memorize one scene
Demo generationTransforming existing teleop demos (timing, start point, grasp, release), re-running them in simulation and keeping only the successful ones (the MimicGen approach)
FK / IKForward kinematics: compute the hand position from joint angles; inverse kinematics: compute joint angles from a desired position
PD controllerProportional–derivative: torque = Kp × (target angle − current angle) − Kd × joint velocity; pulls the joint toward the target like a damped spring
Rate limiterLimits how much a joint command may change from the previous command in each control step (20 ms), up to a threshold (arms 0.2 rad, waist 0.1 rad, hands 1.5 rad)
WBC / AGILEWhole-body controller; AGILE keeps the G1's legs balanced
Wilson 95 %A confidence interval for a success rate, suitable for small numbers of trials
MAEMean absolute error
