SECTION I.02 · INFRASTRUCTURE & PERFORMANCE

Two machines, one VR headset — and the numbers that limit the system.

Simulation, teleop and evaluation run on one workstation; training and model serving run on one remote H100 GPU server. This section describes the configuration used, the software to install on each machine, and the measured performance figures — especially model latency, the most important limit when moving to the real robot.

The model responds more slowly than the time the robot needs to finish one sequence. In simulation this is fine because the simulation pauses and waits; on the real robot, the robot will stall between sequences unless the next call is made in advance and the GPU is placed close to the robot. The model itself takes only ~100 ms; most of the remaining latency lies in the SSH tunnel link and data serialization.

Performance analysis

Reading the three cards above together: at each stage, where time and resources are actually spent, and what that means for the next phase.

INFERENCE
The bottleneck is the link, not the model

The model computes in only ~100 ms, yet each call takes ~1.3 s, longer than one action sequence (0.8 s). The gap lies mostly in the SSH tunnel and data serialization. When 4 robots call at once, latency rises to 3.5–3.9 s because the server processes requests one after another.

DATA COLLECTION
The bottleneck is the video to the headset

Rendering and waiting on CloudXR take 42 % of each loop, nearly 4 times the physics simulation (11 %). RAM grows ~15 MB/s while recording, so each demo should be saved regularly rather than recording one long continuous session.

TRAINING
One H100 is enough, if it is not shared

10,000 fine-tune steps take 61 min and use ≈ 53 GB of GPU memory, which fits one H100. When the GPU is occupied by other jobs, speed drops nearly 8 times (2.9 s/step vs. 0.36 s/step).

Improvement directions: place the GPU server near the robot or on the same local network, and request the next sequence in advance so the robot does not stall; use a wired connection for the headset during data collection; dedicate a GPU to fine-tuning runs.
