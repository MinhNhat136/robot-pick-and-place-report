IV.02 節 · 環境構築

シナリオを再実行するために 2 台のマシンを準備する。

IV.02〜IV.04 節では、報告書の数値を検証するためにシナリオを自分で再実行する手順を説明します。必要なマシンは 2 台です：シミュレーションとノートブックを実行するワークステーション（クライアント）と、GR00T を実行する顧客の GPU サーバー（サーバー）。本節では両側の環境を構築します。サーバーの起動と評価の実行は IV.03 節と IV.04 節で説明します。

ハードウェアとソフトウェアの要件

ワークステーション · CLIENT
シミュレーションとノートブック
  • Ubuntu 24.04、RTX 対応の NVIDIA GPU（本プロジェクトでは RTX 5090）、ドライバー 580
  • Isaac Sim 6.0.1 を ~/isaac-sim-6 にローカルインストール（Python 3.12）
  • Isaac Lab release/3.0.0-beta2 を ~/IsaacLab に配置し、Isaac Sim と同じ Python にインストール
  • Isaac Lab Arena release/0.2.1 を ~/IsaacLab-Arena に配置（関節 YAML ファイルと modality config の取得元）
  • uv、make、git。初回インストール時はインターネット接続が必要
サーバー · SERVER
顧客の GPU サーバー
  • Linux、CUDA 対応の NVIDIA GPU（本プロジェクトでは 1× H100 80 GB）
  • Isaac-GR00T コミット 4b1dca9、uv 環境（Python 3.10）、ffmpeg
  • ベースモデル nvidia/GR00T-N1.7-3B への Hugging Face アクセス権（NVIDIA のライセンスに同意済み）
  • models/ 内のチェックポイントと各シナリオの modality config（カード 5）
  • ワークステーションに向けてポートを開放できること、または SSH を許可できること
バージョンの組み合わせを守ること：報告書の結果はすべて Isaac Sim 6.0.1 + Isaac Lab 3.0.0-beta2 と Isaac-GR00T 4b1dca9 で測定しています。Isaac Sim 6.1 はドライバー ≥ 595 が必要で、このソースコードではまだテストしていません。

ワークステーションへの成果物パッケージの配置

ソースコードは assets/、datasets/、models/ をパス ~/workspace/shimizu-robot/ から読み込むため、パッケージはこの場所に展開してください。Isaac Sim、Isaac Lab、Arena はカード 2 のとおりホームディレクトリに配置します。

~/workspace/shimizu-robot/      # 成果物パッケージ（IV.01）
├── codes/standalone_g1_gr00t/  # クライアント：g1gr00t パッケージ、ノートブック、Makefile
├── assets/                     # nucleus_cache + リンゴ、皿
├── datasets/                   # LeRobot データセット
└── models/                     # チェックポイント（サーバーへコピー、カード 6）
~/isaac-sim-6/   ~/IsaacLab/   ~/IsaacLab-Arena/
別の場所にインストールする場合：Makefile では ISAAC_PY（Isaac Sim の Python）、ARENA_DIR、ISAAC_GR00T_DIR を上書きできます。例：make sim-test ISAAC_PY=/opt/isaac-sim/python.sh。データセットとモデルのパスは configs/*.yaml にあります。

ワークステーションへのクライアントのインストール

standalone_g1_gr00t パッケージは 2 つの環境を使います：.venv（Python 3.10、テストとシミュレーションなしのノートブック用）と Isaac Sim の Python（シミュレーションありのノートブック用）。

cd ~/workspace/shimizu-robot/codes/standalone_g1_gr00t

# .venv 環境
make venv            # uv venv .venv --python 3.10、パッケージ + dev + notebook をインストール
make sync            # ~/IsaacLab-Arena から関節/WBC の YAML ファイル 4 つをコピーし、取得元のハッシュを記録
make assets          # AGILE の脚 policy（ONNX）を assets/wbc/ にダウンロード
make test            # シミュレーション不要の unit test

# Isaac Sim 環境
export PYTHONNOUSERSITE=1   # ~/.local のパッケージが Isaac Sim の Python に混入しないようにする
make sim-install     # パッケージを ~/isaac-sim-6/python.sh にインストール
make sim-test        # Isaac Sim の Python で unit test
make sim-test-scene  # シーンありのテスト：ロボットが安定して立つ、テーブル / リンゴ / 皿
make sim-kernel      # シミュレーション用ノートブックの Jupyter カーネル "isaacsim6" を登録
ワークステーション上のデータパス用途
AGILE の脚 policycodes/standalone_g1_gr00t/assets/wbc/（make assets でダウンロード）すべてのシミュレーション用ノートブック
Galileo シーン、ハンマー、箱、G1 ロボットのアセットassets/nucleus_cache/（パッケージに同梱）リンゴ（Galileo シーン）とハンマーのシナリオ。ネットワーク不要で実行可能
リンゴ、皿assets/objects/リンゴのシナリオ（自作シーン）
ハンマー → 箱 mix200 データセットdatasets/hammer_to_bin/static_hammer_mix200/nb12：デモ再生、画像の色合わせ
NVIDIA のリンゴ → 皿データセットdatasets/isaaclab_arena/static_apple_tutorial/（Hugging Face からダウンロード）デモ再生、リンゴのシナリオの open-loop
確認完了の目安：make test、make sim-test、make sim-test-scene のいずれも失敗したテストがなく、Jupyter でカーネル Isaac Sim Python 3 (isaacsim6) が見えること。

GPU サーバーへのサーバーのインストール

学習時に使ったものと同じコミットの Isaac-GR00T をインストールします。下表は各シナリオに必要なチェックポイントと modality config を示します。それらをサーバーに配置する方法はカード 6 にあります。

# 事前に必要：git、uv、ffmpeg（sudo apt-get install -y ffmpeg）
git clone https://github.com/NVIDIA/Isaac-GR00T.git ~/Isaac-GR00T
cd ~/Isaac-GR00T
git checkout 4b1dca9d88d2a0b9ea5a65aa61c82ff89f5c4f0e
git submodule update --init --recursive
uv sync --python 3.10      # 環境を作成し、GR00T と GPU ライブラリをインストール（数分）
uv run python -c "import gr00t, torch; print('GR00T ok | CUDA', torch.cuda.is_available())"
# ベースモデルが Hugging Face のキャッシュにない場合は、
# nvidia/GR00T-N1.7-3B のライセンスに同意済みのアカウントでログイン：
hf auth login

納品チェックポイントのサーバーへの配置

ファインチューニング済みチェックポイント 3 つは成果物パッケージの models/ フォルダにあり、各フォルダは GR00T サーバーですぐに使えます：重み（safetensors ファイル 3 つ）、設定、processor、正規化統計。検証したいシナリオのチェックポイントだけをコピーすれば十分です。

ステップ 1
サーバーにフォルダを作成
例：~/shimizu-robot/models
ステップ 2
チェックポイントをコピー
ワークステーションから rsync、中断しても再開可能
ステップ 3
完全性の確認
両側のチェックサムを比較し、重みファイル 3 つが揃っていることを確認
ステップ 4
modality config をコピー
リンゴとハンマーのシナリオ用の Arena 版
# ワークステーションで実行
SRV=user@gpu-server
CKPTS="hammer_to_bin_mix200 hammer_to_bin_mix400 real2sim_multi_fruit"
cd ~/workspace/shimizu-robot/models

# ステップ 1 — サーバーにフォルダを作成
ssh $SRV 'mkdir -p ~/shimizu-robot/models ~/shimizu-robot/configs'

# ステップ 2 — 必要なチェックポイントをサブフォルダ構成のままコピー
rsync -avP $CKPTS $SRV:~/shimizu-robot/models/

# ステップ 3 — チェックサムを比較、コピーはしない（-n）：
# ファイルが 1 つも表示されなければ両側は同一
rsync -avnc $CKPTS $SRV:~/shimizu-robot/models/
# 重みファイルの数：期待値は 9（チェックポイント 3 つ × ファイル 3 つ）
ssh $SRV 'ls ~/shimizu-robot/models/*/*/checkpoint-*/*.safetensors | wc -l'

# ステップ 4 — Arena の modality config（リンゴ、ハンマーのシナリオ）
G1=~/IsaacLab-Arena/isaaclab_arena_gr00t/embodiments/g1
rsync -avP $G1/g1_sim_wbc_data_gr00t_n_1_7_config.py \
      $SRV:~/shimizu-robot/configs/
models/ 内のフォルダサーバー上の --model-path のパス
hammer_to_bin_mix200/~/shimizu-robot/models/hammer_to_bin_mix200/
hammer_mix200_n17/checkpoint-10000
hammer_to_bin_mix400/~/shimizu-robot/models/hammer_to_bin_mix400/
hammer_mix400_n17/checkpoint-20000
real2sim_multi_fruit/~/shimizu-robot/models/real2sim_multi_fruit/
g1_fruits_n17_bs32_20k/checkpoint-20000
ネットワーク経由で転送できない場合：models/ フォルダを外付けディスクでコピーし、同じ構成でサーバーに配置します。その場合もステップ 3 は両側の safetensors ファイルに対して sha256sum で実施してください。NVIDIA のリンゴ → 皿チェックポイントはパッケージに含まれないため、Hugging Face からサーバーに直接ダウンロードします。

接続の設定

次の 2 つの方法のいずれかを選びます。サーバー側のポートはクライアントが想定するポート（カード 5）と一致させる必要があります。クライアントのポートは環境変数 NB10_PORT、NB12_PORT または YAML ファイルの server.port フィールドで変更できます。

方法 1
社内ネットワーク
  • サーバーは --host 0.0.0.0 で待ち受け
  • ファイアウォールでシナリオのポートをワークステーションに対してのみ開放
  • クライアントのホストをサーバーの IP に設定。例：NB12_HOST=10.0.0.5
方法 2
SSH トンネル
  • サーバーは --host 127.0.0.1 で待ち受け、ポートを外部に開放しない
  • ワークステーションでトンネルを開き、評価中は開いたままにする
  • クライアントのホストは既定の 127.0.0.1 のまま
# 方法 2、ワークステーションで実行（例：ハンマーのシナリオ、ポート 5557）
ssh -N -L 5557:127.0.0.1:5557 user@gpu-server
